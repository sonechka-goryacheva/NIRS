# НИРС: справочник IT-команд с RAG

«Справочник IT-команд» помогает подобрать консольную команду по описанию задачи обычными словами
(«не хватает прав при запуске скрипта», «что делает du -sh») или объяснить уже известную команду.
Ответ строится по собственному датасету команд: поиск BM25 находит кандидатов, LLM оформляет ответ —
название, команда, описание и 3 примера применения. Веб-чат работает после входа или в гостевом режиме
(без регистрации, история до выхода); роли user и admin. Есть обучение — тесты по темам с повтором ошибок. Личные чаты сохраняются до удаления, их можно искать
и переименовывать. Пользователь может загрузить свой датасет (JSON/CSV) — поиск учитывает его вместе с общим.
Светлая и тёмная темы.

В репозитории есть локальный фронтенд на HTTP-моках (макет интерфейса для КТ1): он работает без сервера,
аккаунты и ответы в нём учебные. Поиск — собственный индекс BM25 с оценкой качества — в папке `rag/`, корпус — в `data/`.
Сервер FastAPI, который свяжет интерфейс с настоящими авторизацией, поиском и LLM, ещё не реализован.

> Фронтенд находится в ветке `feature/web-frontend` (pull request в `main`). После слияния — в папке `web/`.

## Запуск проекта

Нужен Python 3.10+. Все команды — из корня репозитория.

**1. Зависимости**

    python3 -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
    pip install -r requirements.txt

**2. Настройки LLM (`.env`)** — нужны только для ответов настоящей нейросети; без них работает заглушка
(ответ собирается из найденных команд без обращения к API).

    cp .env.example .env
    # в .env: USE_STUB=false и OPENAI_API_KEY=sk-…  (USE_STUB=true — заглушка, значение по умолчанию)

**3. RAG в терминале.** Сервер FastAPI (`app/api.py`) ещё не реализован (см. «Следующие шаги»), поэтому RAG
демонстрируется скриптом — вопрос → top-3 BM25 с ID и баллами → промпт с найденными командами → ответ LLM со ссылками:

    python rag/demo.py                                        # 3 примера: два вопроса по теме и один не по теме
    python rag/demo.py "не хватает прав при запуске скрипта"  # свой вопрос

Без `.env` ответ даёт заглушка (собирает его из найденных команд); с `USE_STUB=false` и `OPENAI_API_KEY` — OpenAI.
На вопрос не по теме («Как приготовить пасту?») LLM не вызывается: «Подходящая команда не найдена…».
Консольный чат приложения — `python -m app.main`; только поиск с разбором предобработки — `python -m rag search "…" --explain`.

**4. Фронтенд** (веб-интерфейс на моках: работает без бэкенда, аккаунты и ответы учебные):

    python3 web/serve.py

Открыть http://localhost:8080. Сервер `serve.py` отдаёт файлы без кэша и пишет запросы в терминал;
если порт занят, запустится на следующем свободном. Страницы: вход, регистрация, гостевой режим, чат с историей,
справочник команд, «Мои команды», обучение, профиль; для admin — редактирование справочника и пользователи.
Все адреса — `spec/tech/ui_tech.md`.

## Запуск бенчмарка

Оценка поиска по методичке НИРС — одной командой:

    python rag/evaluate.py                # Recall@3, MRR (+ Recall@1/5/10, MRR@3), темы и разбор по каждому вопросу:
                                          # top-3 с ✓/✗ и какие эталонные команды не попали в top-3
    python rag/evaluate.py --compare      # + сравнение вариантов предобработки и параметров BM25
    python -m pytest                      # 30 тестов: формулы BM25, метрики, разметка, демо, обёртка app/

Где что лежит:
- **Вопросы и эталонная разметка** — `rag/queries.json`: 46 вопросов, у каждого 3–5 правильных команд (`relevant`, id вида `git-3`),
  и 7 вопросов не по теме (`negative`).
- **Результаты «до / после» дополнения тегов** — `rag/results/README.md` (таблица) и полные прогоны `before_tags.txt`,
  `after_tags.txt` рядом; итоговая таблица и выводы — `rag/REPORT.md`, раздел 7.
- Прежний бенчмарк (Top-3 accuracy, одна ожидаемая команда) — `python benchmark/run.py`, оставлен для истории.

| | Recall@3 | MRR | MRR@3 |
|---|---|---|---|
| До дополнения тегов | 0,312 | 0,552 | 0,511 |
| **После (текущий корпус)** | **0,447** | **0,777** | **0,757** |

## Сценарий проверки

**RAG (`python rag/demo.py "…"`):**
- «не хватает прав при запуске скрипта» → `[powershell-17] Set-ExecutionPolicy` и `[linux-13] chmod` (Windows и Linux/macOS);
- «откатить неудачный коммит» → `git revert`, `git reset`; «что делает du -sh» → `du -sh` (объяснение команды);
- «Как приготовить пасту?» → поиск пуст, LLM не вызывается: «Подходящая команда не найдена. Попробуйте описать задачу другими словами.»

**Источник ответа:** демо печатает под ответом «Источники» — ID команды и место в корпусе
(`[linux-13] Права доступа — data/corpus/linux.json, запись № 13`), а на этапе Retrieval — балл BM25 и вклад каждого слова;
в веб-интерфейсе у карточки — категория и платформа, команду можно открыть в «Справочнике команд».

**Веб-интерфейс** (`python3 web/serve.py`, логины — выше):
- гостевой режим: «Продолжить без регистрации» → задать вопрос → плашка «Зарегистрируйтесь, чтобы сохранить историю»;
  чат можно переименовать и найти поиском; после «Выйти» история гостя удаляется;
- «Забыли пароль?» — логин `demo` и код `DEMO-7K2P-Q9XA`, старый пароль не нужен;
- переключатель темы (луна/солнце), поиск и переименование чатов в боковой панели;
- «Мои команды» → загрузить файл (шаблон JSON/CSV в том же окне) → спросить в чате о своей команде;
- под admin: «Справочник команд» → команда → «Редактировать» (сразу форма этой команды, «Назад» возвращает);
- «Обучение» → тема → тест, ошибки — «Повторить ошибки».

Полный список сценариев — `spec/product/scenarios.md` (проверять под ролями гость, user, admin, на ширине компьютера
и телефона). Веб-интерфейс пока на моках: поиск в нём — упрощённая имитация на JS, настоящий BM25 — в `rag/`
(подключится к интерфейсу через сервер).

## Моки и интеграция

Экраны обращаются к серверу только через `web/assets/js/api/` (обычный `fetch`, сессия в cookie).
Мок подменяет `fetch` для `/api/*` и отвечает как сервер: те же пути, коды, `{detail, field}`.
Переход на сервер: в `web/assets/js/config.js` поставить `useMock: false` и удалить папку `web/assets/js/mock/` —
остальной код не меняется. Подробно — `spec/tech/ui_tech.md`, контракт — `spec/tech/api.md`.

## Дизайн

Мятная палитра со «стеклянными» плашками в двух темах — тёмной изумрудной и светлой мятной — на всех экранах;
по умолчанию как в системе, переключатель на входе, в боковой панели и в профиле. Окна, подтверждения и выпадающие
списки — свои, в оформлении темы (не системные).
Иллюстрация входа — изометрические клавиши `>_`, `Ctrl`, `C`, `Tab`; логотип — две плашки со строками текста.
Шрифты Inter и JetBrains Mono. Все цвета — токены в `web/assets/css/theme.css`. Описание — `spec/product/design.md`.

# Сценарии использования

## Сценарий 1. Запрос по проблеме

### Шаги
1. Пользователь пишет: «не хватает прав при запуске скрипта».
2. Нейросеть ищет по полям command + description + tags.
3. Возвращает лучшую команду полностью и до 2 похожих (раскрываются по нажатию).

### Формат ответа
1. Название
2. Команда: chmod +x script.sh
3. Описание: делает файл исполняемым...
4. Примеры применения:
   - chmod +x deploy.sh
   - chmod +x backup.sh
   - chmod -R +x scripts/

---

## Сценарий 2. Объяснение команды

### Шаги
1. Пользователь пишет: «что делает du -sh».
2. Нейросеть находит команду в датасете.
3. Возвращает формат ответа как в сценарии 1.

---

## Сценарий 3. Просмотр датасета

### Шаги
1. Пользователь открывает боковую панель.
2. Нажимает «Датасет команд».
3. Выбирает категорию (Linux, Git, Docker...).
4. Видит список команд.
5. Нажимает на команду → открывается полное описание.

### Назначение
Проверка и общее ознакомление с командами,
отобранными в качестве датасета.

---

## Сценарий 4. Команда не найдена

### Шаги
1. Пользователь пишет запрос, по которому нет уверенного совпадения.
2. Если в датасете есть команды, где совпали значимые слова запроса, нейросеть отвечает:
   > «Подходящая команда не найдена. Возможно, подойдут указанные ниже варианты?»
   и показывает до 3 таких команд, каждую полностью, как в обычном ответе.
3. Если совпадений нет совсем (бессмыслица, тема не про IT, например «кракозябра») — только жёлтое сообщение:
   > «Подходящая команда не найдена. Попробуйте описать задачу другими словами.»
   Случайные команды не показываются.

---

## Сценарий 5. Администратор редактирует датасет

### Шаги
1. Админ открывает «Редактировать датасет» в боковой панели.
2. Выбирает категорию и команду или нажимает «Новая команда».
3. Заполняет форму (3 примера, не меньше 5 тегов) и сохраняет, либо удаляет команду с подтверждением.
4. Изменения сразу видны в датасете и учитываются поиском.

---

## Сценарий 6. Уточняющий вопрос

### Шаги
1. Пользователь что-то не понял или хочет уточнить.
2. Задаёт последующий вопрос в том же чате.
3. Нейросеть учитывает контекст и снова подбирает команду.

---

## Сценарий 7. История чатов

### Шаги
1. Пользователь открывает боковую панель.
2. Видит список прошлых чатов.
3. Нажимает на один → возвращается к старой переписке.

---

## Сценарий 8. Удаление чата

### Шаги
1. Пользователь наводит на чат в истории и нажимает «Удалить».
2. Подтверждает удаление.
3. Чат исчезает из истории; если он был открыт — открывается новый чат.

---

## Сценарий 9. Администратор управляет пользователями

### Шаги
1. Админ открывает «Пользователи» в боковой панели.
2. Находит пользователя поиском по логину или фильтром по роли.
3. Может:
   - создать пользователя с ролью «Пользователь» или «Администратор»;
   - изменить роль или задать новый пароль;
   - удалить пользователя вместе с его историей чатов (с подтверждением).
4. Себя удалить и понизить нельзя; последний администратор остаётся всегда.
5. Содержимое чужих чатов админ не видит — только их количество.

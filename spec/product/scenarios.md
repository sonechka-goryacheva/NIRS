# Сценарии использования

## Сценарий 1. Запрос по проблеме

### Шаги
1. Пользователь пишет: «не хватает прав при запуске скрипта».
2. Нейросеть ищет по полям command + description + tags.
3. Возвращает лучшую команду полностью и до 2 похожих (раскрываются по нажатию).

### Формат ответа
1. Название
2. Команда: chmod +x script.sh
3. Описание: делает файл исполняемым...
4. Примеры применения:
   - chmod +x deploy.sh
   - chmod +x backup.sh
   - chmod -R +x scripts/

---

## Сценарий 2. Объяснение команды

### Шаги
1. Пользователь пишет: «что делает du -sh».
2. Нейросеть находит команду в датасете.
3. Возвращает формат ответа как в сценарии 1.

---

## Сценарий 3. Просмотр датасета

### Шаги
1. Пользователь открывает боковую панель.
2. Нажимает «Справочник команд».
3. Выбирает категорию (Linux, Git, Docker...).
4. Видит список команд.
5. Нажимает на команду → открывается полное описание.

### Назначение
Проверка и общее ознакомление с командами,
отобранными в качестве датасета.

---

## Сценарий 4. Команда не найдена

### Шаги
1. Пользователь пишет запрос, по которому нет уверенного совпадения.
2. Если в датасете есть команды, где совпали значимые слова запроса, нейросеть отвечает:
   > «Подходящая команда не найдена. Возможно, подойдут указанные ниже варианты?»
   и показывает до 3 таких команд, каждую полностью, как в обычном ответе.
3. Если совпадений нет совсем (бессмыслица, тема не про IT, например «кракозябра») — только жёлтое сообщение:
   > «Подходящая команда не найдена. Попробуйте описать задачу другими словами.»
   Случайные команды не показываются.

---

## Сценарий 5. Администратор редактирует датасет

### Шаги
1. Админ открывает «Редактировать датасет» в боковой панели.
2. Выбирает категорию и команду или нажимает «Новая команда».
3. Заполняет форму (3 примера, не меньше 5 тегов) и сохраняет, либо удаляет команду с подтверждением.
4. Изменения сразу видны в датасете и учитываются поиском.

---

## Сценарий 6. Уточняющий вопрос

### Шаги
1. Пользователь что-то не понял или хочет уточнить.
2. Задаёт последующий вопрос в том же чате.
3. Нейросеть учитывает контекст и снова подбирает команду.

---

## Сценарий 7. История чатов

### Шаги
1. Пользователь открывает боковую панель.
2. Видит список прошлых чатов.
3. Нажимает на один → возвращается к старой переписке.
4. Если чатов много — вводит слово в «Поиск по истории» (например, «chmod»): остаются чаты, где оно есть
   в названии, запросе или команде ответа; под названием — фрагмент, где нашлось.
5. Может переименовать чат: карандаш у чата в истории.

---

## Сценарий 8. Удаление чата

### Шаги
1. Пользователь наводит на чат в истории и нажимает «Удалить».
2. Подтверждает удаление.
3. Чат исчезает из истории; если он был открыт — открывается новый чат.

---

## Сценарий 9. Администратор управляет пользователями

### Шаги
1. Админ открывает «Пользователи» в боковой панели.
2. Находит пользователя поиском по логину или фильтром по роли.
3. Может:
   - создать пользователя с ролью «Пользователь» или «Администратор»;
   - изменить роль или задать новый пароль;
   - удалить пользователя вместе с его историей чатов (с подтверждением).
4. Себя удалить и понизить нельзя; последний администратор остаётся всегда.
5. Содержимое чужих чатов админ не видит — только их количество.

---

## Сценарий 10. Гостевой режим

### Шаги
1. На странице входа пользователь нажимает «Продолжить без регистрации».
2. Сразу попадает в чат, может спрашивать, смотреть историю и датасет.
3. Видит предупреждение: история удалится после выхода.
4. Нажимает «Зарегистрироваться» → регистрация (предупреждение: чаты гостя не переносятся) → получает код восстановления.
5. Или нажимает «Выйти» → подтверждает → чаты гостя удаляются.

---

## Сценарий 11. Забыли пароль

### Шаги
1. При регистрации пользователь сохраняет код восстановления.
2. Забыв пароль, на странице входа нажимает «Забыли пароль?».
3. Вводит логин, код и новый пароль дважды.
4. Получает новый код (старый сгорел) и входит с новым паролем.
5. Нет кода — обращается к администратору, тот задаёт новый пароль в «Пользователях».
6. Вошедший пользователь меняет пароль в профиле без старого и может выпустить новый код.

---

## Сценарий 12. Свой датасет

### Шаги
1. Пользователь открывает «Датасет команд» → «Мои команды».
2. Скачивает шаблон JSON или CSV, заполняет своими командами.
3. «Загрузить файл» → перетаскивает файл → «Загрузить».
4. Видит «Добавлено N, пропущено M» и причины для пропущенных строк.
5. Спрашивает в чате — поиск учитывает его команды вместе с общими; карточка помечена «Мои команды».
6. Ошибку в своей команде исправляет карандашом в списке или кнопкой «Редактировать» на карточке.

---

## Сценарий 13. Нашёл ошибку в датасете — сразу исправил (admin)

### Шаги
1. Администратор смотрит команду в датасете и видит ошибку.
2. Нажимает «Редактировать» на карточке (или карандаш в строке списка).
3. Открывается «Редактировать датасет» сразу с формой этой команды и нужной категорией.
4. Сохраняет; «Назад» (стрелка слева в шапке) возвращает туда, откуда пришёл — к карточке или списку;
   кнопка «В датасете» открывает карточку команды.

---

## Сценарий 14. Обучение и закрепление

### Шаги
1. Пользователь открывает «Обучение» в боковой панели и выбирает тему (например, Git).
2. Нажимает «Начать тест», выбирает 10 вопросов или всю тему (если в теме ≤ 10 команд — тест начинается сразу) и проходит тест: подобрать команду под задачу, объяснить команду,
   назвать её, узнать пример применения. Следующий тест начнётся с команд, которых ещё не было.
   Тема «Мои команды» — тест по своему загруженному датасету.
3. После каждого ответа видит, верно ли, и карточку команды — закрепляет материал.
4. В конце — процент верных и лучший результат по теме; ошибки попадают в «Повторить ошибки».
5. Повторяет ошибки отдельным тестом: верный ответ убирает команду из списка. Когда ошибок нет — тема закреплена.
6. Прогресс сохраняется (у гостя — до выхода); при желании его можно сбросить.

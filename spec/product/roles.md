# Роли и права

Две роли: **user** (пользователь, IT-специалист) и **admin** (администратор).
Гость (не вошёл) видит только вход, регистрацию и смену пароля.

## Матрица прав

| Действие | Гость | user | admin |
|---|:-:|:-:|:-:|
| Регистрация (создаётся только роль user) | ✓ | — | — |
| Вход, смена пароля по логину и текущему паролю | ✓ | ✓ | ✓ |
| Выход | — | ✓ | ✓ |
| Профиль: свой логин, роль, дата регистрации | — | ✓ | ✓ |
| Чат: новый запрос, уточняющие вопросы | — | ✓ | ✓ |
| История: просмотр и удаление **своих** чатов | — | ✓ | ✓ |
| Датасет: просмотр категорий, списков, карточек | — | ✓ | ✓ |
| Датасет: добавить, изменить, удалить команду | — | — | ✓ |
| Пользователи: список с поиском и фильтром по роли | — | — | ✓ |
| Пользователи: создать с ролью user или admin | — | — | ✓ |
| Пользователи: изменить роль, задать новый пароль | — | — | ✓ |
| Пользователи: удалить (вместе с историей чатов) | — | — | ✓ |

## Правила
1. Регистрация всегда создаёт роль user. Роль из запроса игнорируется.
2. Первого администратора создают вручную: `python -m app.auth admin <логин>`. Дальше администраторы назначаются в интерфейсе.
3. Администратор не может удалить себя и изменить свою роль.
4. В системе всегда остаётся хотя бы один администратор: последнего нельзя понизить или удалить.
5. Администратор **не видит** содержимое чатов других пользователей — только их количество. История — личные данные.
6. Чужой чат для пользователя «не существует»: сервер отвечает 404, а не 403.
7. Права проверяет сервер на каждом запросе. Скрытие кнопок в интерфейсе — только удобство, не защита.
8. Смена роли или удаление действуют сразу: при следующем запросе пользователь получит новые права или 401.

## Что сознательно не входит
- Восстановление пароля по почте (нет почты в данных).
- Блокировка без удаления, журнал действий администратора — можно добавить позже (см. CHANGE_HISTORY).

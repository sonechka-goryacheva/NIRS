# Оценка качества поиска

## Назначение

Проверка качества ранжирования по методичке НИРС: тестовый набор запросов, равномерно покрывающий корпус,
не меньше трёх релевантных документов на запрос, метрики Recall@k и MRR.

## Файлы

- `rag/queries.json` — тестовый набор: `queries` (id, тема, запрос, список релевантных id команд) и `negative`
  (запросы не по теме — ожидается ответ «ничего не найдено»).
- `rag/evaluate.py`, `rag/metrics.py` — расчёт метрик, покрытие корпуса, сравнение вариантов.
- `rag/REPORT.md` — результаты и выводы.
- `rag/results/` — зафиксированные прогоны «до» и «после» дополнения тегов и корпус «до» (rag/results/README.md).

## Исторический бенчмарк `benchmark/`

Прежняя проверка — 20 запросов «запрос → одна ожидаемая команда», метрика Top-3 accuracy (`benchmark/cases.json`,
`benchmark/run.py`). Оставлена в проекте для сравнения и вопросов на защите, но **не является основной оценкой**:
методичка требует ≥ 3 релевантных документа на запрос и метрики Recall@k, MRR. Скрипт вызывает `app.search`,
то есть работает уже на новом поиске `rag/`: было 15/20 (75 %) на rank-bm25, стало 18/20 (90 %).

    python benchmark/run.py

## Правила тестового набора

- Запрос — задача пользователя своими словами, не копия текста корпуса.
- Релевантны все команды корпуса, решающие задачу, в том числе из других категорий (Linux, PowerShell, macOS…).
- У каждого запроса не меньше 3 релевантных — проверяется при загрузке.
- Все категории корпуса представлены среди релевантных (сейчас 134 из 149 команд, по категориям ≥ 80 %).
- При изменении корпуса (новые команды, другие id) набор обновляется вместе с ним.

## Метрики

- Recall@k (k = 1, 3, 5, 10) = 1/|Q| · Σ |R_q ∩ Top_k(q)| / |R_q|; рядом выводится максимум возможного (min(k, |R_q|)/|R_q|).
- MRR = 1/|Q| · Σ 1/rank_q, rank_q — позиция первого релевантного документа во всей выдаче (нет в выдаче — 0), как в методичке.
- MRR@3 — то же по top-3: первый релевантный ниже 3-й позиции (или его нет) — 0. Чат показывает 3 команды.
- Доля запросов не по теме, получивших ответ «ничего не найдено».

## Запуск

    python rag/evaluate.py             # одной командой: метрики, темы, разбор по каждому вопросу (что нашлось, что нет)
    python -m rag eval                 # метрики и разбивка по темам
    python -m rag eval --corpus rag/results/corpus_before_tags   # прогон на корпусе «до» дополнения тегов
    python -m rag eval --details       # по каждому запросу
    python -m rag eval --compare       # варианты предобработки и сетка k1 × b
    python -m pytest rag               # в т.ч. проверка, что MRR ≥ 0,7 и Recall@5 ≥ 0,5

# tochka_2 — обмен с другой командой

Проверка своего поиска на чужих документах и вопросах. Чужой набор лежит в `data/`: 30 конспектов о питании (D01–D30) и 15 вопросов (Q01–Q10 и ловушки T01–T05), версия nutrition-counter-classroom-v1. Эталоны в индекс не входят.

Индекс — обратный индекс и BM25 этого проекта (`vendor/bm25.py`, `vendor/text.py`, те же файлы, что `rag/`). Готовые поисковые библиотеки не используются. Статья записывается в поля, которые индексирует справочник: название, текст, ключевые слова. Конспект короче 900 символов, поэтому он индексируется целиком, без нарезки.

Параметры те же, что у рабочего поиска, и на этих вопросах не подбирались: k1 = 0,5, b = 0,75, три документа в контексте, тип «найдено» при балле не ниже 5.

## Запуск

Из корня репозитория, в окружении проекта (нужен pymorphy3):

```bash
python tochka_2/run_eval.py
```

Скрипт заново строит индекс и пишет:

- `results/report.md` — метрики и таблица классов E1–E6;
- `results/run.json` — выдача, баллы, ранги;
- `results/answers.md` — текст, который вернула заглушка.

Генерация идёт штатной заглушкой проекта: ключа OpenAI нет, локальной модели нет. Заглушка переносит найденный текст и не дописывает факты. Классы E3 и E4, которые видны только у живой модели, на этом прогоне не возникают. Отказ на ловушке считается по той же фразе, что в `app/llm.py`: «Подходящая команда не найдена».
